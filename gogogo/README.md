## 1. 项目定位

这个项目的核心不是写代码，而是把你做过的项目沉淀成可复用的成长资产。

- 主目标：从每个项目中提炼经验，持续改进工作流程与决策质量。
- 关键主题：每做一个项目，都要有“可验证的进步”。
- 使用方式：可在 Codex、Claude Code 等工具中交替使用，不依赖单一模型结论。

## 2. 我对你需求的理解（确认版）

你需要一个“长期反思系统”，它应同时满足：

1. 能记录每个项目的收获、问题、经验和改进点。
2. 能把资源、方法、工具统一收口，并且有链接可追溯。
3. 能定义清晰的输入规范（你要提供什么）。
4. 能定义清晰的输出规范（系统要产出什么）。
5. 能定义检查标准（怎么判断这次复盘是否合格）。
6. 能整合你已安装的技能（`gstack`、`superpower`、`dbskill`）形成固定工作流。

## 3. 项目目标与非目标

### 目标

- 把“项目经历”转化为“下次可执行改进”。
- 建立一套长期可维护的复盘标准。
- 让不同模型互相校验，降低主观偏差。
- 把外部对标资料（如 `guishou_56_ai_saas_index.docx`）转为可执行方法并持续落地。

### 非目标

- 不追求把这里变成代码主仓库。
- 不追求记录所有细节日志（只保留对成长有价值的信息）。

## 4. 标准流程（Input -> Process -> Output）

1. 输入采集：按模板提交项目信息与证据链接。
2. 结构化分析：围绕目标、结果、偏差、原因、改进进行复盘。
3. 产出沉淀：输出结论、方法更新、下次行动项。
4. 质量检查：按检查清单评分，不达标则返工。
5. 复用落地：把可复用方法写入资源索引并在下个项目应用。

## 4.1 对标资料融合流程（Benchmark -> Action）

1. 从对标资料中提炼 3-5 条“可执行方法”（不能只记观点）。
2. 逐条映射到当前项目中的具体位置（页面、功能、渠道、转化环节）。
3. 为每条方法设定验证指标（如注册转化率、留存、付费率、爬虫收录）。
4. 在下一个迭代中执行并复盘结果，更新方法库。

## 5. 输入规范（你需要提供什么）

每次复盘最少提供：

- 项目类型与背景（如：网站/小程序/自动化流程）
- 目标与预期结果
- 实际结果（数据或事实）
- 关键过程证据（文档、截图、链接、提交记录）
- 主要问题与关键决策
- 你主观认为“本次最大收获/最大损失”

模板见：[PROJECT_REFLECTION_TEMPLATE.md](/Users/bai/code/gogogo/templates/PROJECT_REFLECTION_TEMPLATE.md)

## 6. 输出规范（系统必须产出什么）

每次复盘至少输出 5 类结果：

1. 项目结论摘要（发生了什么，为什么）
2. 3 条可复用经验（下次可直接执行）
3. 3 条待避免错误（触发条件 + 预防动作）
4. 下一项目行动项（含优先级、截止时间、验证方式）
5. 方法库更新（哪些流程/检查项应被修改）
6. 对标经验映射表（借鉴了谁的哪条方法，落到你哪个项目）

## 7. 检查标准（如何判断复盘是否合格）

使用 10 分制，`>= 8` 视为通过：

- 完整性（0-2）：输入信息是否齐全
- 证据性（0-2）：每个关键判断是否有链接或事实支撑
- 可执行性（0-2）：行动项是否明确到“谁在何时做什么”
- 可复用性（0-2）：经验是否可迁移到下个项目
- 成长性（0-2）：是否明确“这次比上次进步了什么”

强制检查项（任一不满足即不通过）：

- 每次复盘至少包含 1 条来自对标资料的落地尝试。
- 每次复盘至少关联 1 个真实项目证据链接。
- 每次复盘至少产出 1 条“下个迭代立即执行”的改进行动。

## 9. 技能协同（gstack / superpower / dbskill）

- `gstack`：偏执行与工程质量（流程化、验证、复盘落地）。
- `superpower`：偏工作流编排与跨工具协作。
- `dbskill`：偏诊断与思考框架，帮助提炼更高质量结论。

建议策略：

1. 先用一个模型产出初版复盘。
2. 用第二个模型做“反驳式检查”（找漏洞、找证据不足）。
3. 合并后按检查清单打分，未达标继续迭代。

## 9.1 多工具交替检查标准（Codex / Claude Code）

建议固定为 3 轮：

1. 轮次 A（主模型产出）：完成初版复盘结论与行动项。
2. 轮次 B（第二模型质疑）：重点查证据缺失、逻辑跳跃、伪改进。
3. 轮次 C（主模型收敛）：只保留有证据且可执行的结论，更新最终版。

最终交付必须满足：

- 结论可被证据追溯；
- 行动项可被执行与验证；
- 能明确回答“下一次如何做得更好”。

## 10. 最小使用步骤（从今天开始）

1. 复制模板并填写一次项目复盘。
2. 用检查清单评分。
3. 把新增方法与资料写入资源索引。
4. 在下一个项目开始前，先读上一次行动项并执行。

### 三 skill 审查分工（建议）

1. `gstack`：做站点实测（页面流程、表单、移动端、截图证据）。
2. `superpower`：做流程性校验（是否按标准执行，是否有验证证据）。
3. `dbskill`：做商业与增长诊断（需求、转化、增长路径是否成立）。

### 推荐执行顺序

1. 先用 `gstack` 拿到事实证据（不要先下结论）。
2. 再用 `dbskill` 判断“为什么有问题”和“该优先改什么”。
3. 最后用 `superpower` 检查本轮结论是否达到可执行标准。
